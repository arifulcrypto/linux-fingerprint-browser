# 09 — 路线图

路线图按**每单位投入降低多少风险**排序。它刻意把 Chromium 分支推迟到配置文件契约和测量
工具稳定之后。

---

## 阶段 0 —— 清单（已完成）

**目标：** 准确了解当前环境。

交付物：

- 只读主机和容器采集脚本；
- `inventory/` 下的脱敏清单；
- 指纹探针（有头 + 无头）；
- 代理和网络地图；
- 本文档。

退出标准：

- 关于环境的每个断言都有证据文件或可复现命令；
- 不发布任何凭据或公网地址；
- 快照标注日期和版本。

**状态：** 2026-11-12 完成。

---

## 阶段 1 —— 基础（4–6 周）

**目标：** 让测量可重复，让构建路径真实可行。

交付物：

1. **自测工具** —— 一个页面 + 运行器，捕获 `06-fingerprint-surface.md` 中的契约，并与
   清单做 diff。
2. **配置文件 schema v1** —— JSON/YAML，包含 seed、人格、网络、自动化、生命周期。
3. **网络命名空间原型** —— 每配置文件 netns，带代理、DNS、IPv6 关闭和 kill switch。
4. **构建环境** —— 独立构建机，带 `depot_tools`、clang、ninja、ccache、≥100 GB 磁盘。
5. **CI** —— 脱敏检查（已有）、文档链接检查、schema 校验、补丁应用检查。
6. **基线 canary 套件** —— 10–20 个公开指纹/泄漏测试页，有头运行。

退出标准：

- 自测在当前 VPS 上运行并产生稳定 JSON 报告；
- 配置文件可在无直接出口的网络命名空间中启动；
- Chromium 检出在构建机上完成 `gn gen`；
- CI 阻止泄漏 UUID、密钥或真实 IP 的提交。

**风险：** 命名空间网络比较棘手；VPS 没有空闲磁盘；构建机是新依赖。

---

## 阶段 2 —— MVP 配置文件管理器（6–8 周）

**目标：** 在**原版 Chrome** 上交付可用产品，不分支。

交付物：

1. **配置文件服务** —— 创建、列出、启动、停止、删除、快照、恢复。
2. **运行时监管程序** —— 每配置文件容器或命名空间、显示、Chrome 启动、资源限制、
   崩溃重启。
3. **指纹包** —— 时区、区域、`Accept-Language`、屏幕、字体、WebGL 参数
   （`--enable-unsafe-swiftshader --ignore-gpu-blocklist`）。
4. **网络平面** —— 每配置文件代理、远程 DNS、IPv6 关闭、fail-closed、泄漏测试。
5. **UI/API** —— 最小 Web UI 和 REST API；API token；审计日志。
6. **启动时自测** —— 检查失败时阻止或警告。
7. **配置文件生命周期** —— 临时配置文件、存储配额、缓存清理。

退出标准：

- 一台主机上 10 个并发配置文件，每个有不同出口和一致的时区/区域；
- canary 套件中零直接出口泄漏；
- 配置文件在主机重启后恢复并回到相同状态；
- 代理失败时阻止配置文件（无直接回退）；
- 操作员可在两分钟内创建并启动配置文件。

**风险：** 内存（3.8 GiB 很紧）、磁盘（剩余 2 GiB）、共享 Docker 栈。MVP 可能需要更大
主机或更少并发配置文件。

---

## 阶段 3 —— Chromium 分支 alpha（8–12 周）

**目标：** 控制配置无法修复的信号。

交付物：

1. **固定 Chromium 检出**和可复现构建。
2. **补丁集 v1：**
   - UA-CH/平台一致性；
   - 渲染器中按配置文件时区/区域；
   - WebGL/WebGPU 厂商/渲染器和参数虚拟化；
   - 确定性 canvas/音频噪声；
   - 字体度量虚拟化（或精选字体集）。
3. **自测集成** —— 每个补丁有测试和 diff。
4. **打包** —— `.deb`/AppImage、版本、签名、回滚。
5. **补丁 rebase 手册** —— 如何迁移到下一个 Chromium 里程碑。

退出标准：

- 分支通过与原版 Chrome 相同的自测，加上补丁检查；
- WebGL 可用且与声称的 GPU 一致；
- Windows 人格要么支持，要么明确不在范围；
- Chromium 里程碑更新可在计划窗口内 rebase。

**风险：** 补丁维护、构建时间、二进制大小、编解码器/Widevine 缺口、安全响应。

---

## 阶段 4 —— 自动化、AI/MCP 与协作（8–12 周）

**目标：** 让配置文件可编程、可共享。

交付物：

1. **CDP 网关**，带认证、按配置文件授权和审计。
2. **Playwright/Puppeteer 集成**，通过 `connectOverCDP`。
3. **MCP 服务器**，提供配置文件/浏览器/指纹工具。
4. **团队功能** —— 角色、共享、配额、活动日志。
5. **导入/导出** —— 加密配置文件包。
6. **可观测性** —— 仪表盘、告警、自测历史。

退出标准：

- 自动化会话不能覆盖代理/指纹参数；
- `navigator.webdriver` 和自动化痕迹匹配配置文件策略；
- 团队可共享配置文件而不共享凭据；
- 每个自动化操作可归因。

**风险：** 自动化检测、凭据处理、多租户隔离。

---

## 阶段 5 —— 生产加固（持续）

**目标：** 安全地规模化运营。

交付物：

- 沙箱化、非 root 浏览器运行时；
- 加密存储和密钥轮换；
- 签名更新和回滚；
- 主机集群管理和调度；
- 事件响应和披露政策；
- 如市场需要，支持 Windows/WSL；
- 性能和密度调优；
- 合规审查（隐私、出口、供应商条款）。

退出标准：

- 进程列表或日志中没有共享密钥；
- 被攻破的配置文件无法访问另一个配置文件的数据或网络；
- 更新失败自动回滚；
- 安全审查签字。

## 跨领域工作流

| 工作流 | 时间 | 说明 |
|---|---|---|
| 测量 / canary 套件 | 阶段 1 起 | 随每个补丁增长 |
| 安全加固 | 阶段 1 起 | 非 root、沙箱、密钥、审计 |
| 文档 / i18n | 每个阶段 | 英文优先，中文镜像 |
| 构建/发布工程 | 阶段 1 起 | 与运行时分离 |
| 代理质量 / 成本 | 阶段 2 起 | 住宅按流量计费；不要自动测试循环 |
| 法律 / ToS 审查 | 发布前 | 指纹隔离是双用途 |

## 风险与缓解

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 检测军备竞赛 | 高 | 高 | 一致性 + 测量，不是一次性伪造 |
| Chromium 补丁维护 | 高 | 高 | 小补丁、测试、rebase 预算 |
| 代理成本/质量 | 中 | 高 | 会话基准、配额、供应商多样化 |
| 磁盘耗尽 | 高 | 高 | 独立浏览器主机、配额、清理 |
| 内存压力 | 高 | 中 | 每主机更少配置文件、限制、监控 |
| 凭据泄漏 | 中 | 高 | 密钥管理器、脱敏 CI、最小权限 |
| 法律/ToS 挑战 | 中 | 高 | 明确可接受使用政策、法律顾问审查 |
| 单 VPS 故障 | 中 | 高 | 控制平面分离、备份、放置 |
| Windows 人格缺口 | 高 | 中 | 先原生 Linux；之后 VM/分支 |

---

## 关键指标

- 配置文件启动成功率；
- 按检查项的自测通过率；
- 每 1000 次启动的泄漏事件（目标：0）；
- canary 检测率（内部，不构成保证）；
- 启动时间中位数；
- 按版本的 Chrome 崩溃率；
- 构建节奏和 rebase 时间；
- 每个活跃配置文件的月成本。
